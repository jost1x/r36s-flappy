# R36S y despliegue

## Compilación ARM64

La build para R36S usa Docker y Debian Buster para mantener compatibilidad con la versión de glibc de ArkOS. Raylib se compila con el backend DRM/KMS y renderizado por software: no depende de un servidor X11 ni de que el driver 3D esté disponible.

```sh
make r36s
```

El resultado queda en `bin/r36s-arm64/r36s-flappy`.

## Despliegue

```sh
export R36S_IP=192.168.1.100
export R36S_USER=ark  # opcional
make deploy
```

El script instala el binario en `/opt/r36s-app/bin` y añade un lanzador `r36s-flappy.sh` al directorio de Ports si lo encuentra.

## Requisitos en R36S

- ArkOS con acceso SSH habilitido
- Usuario `ark` (o el que configures con `R36S_USER`)
- Docker con buildx en la máquina de desarrollo

## Checklist de estabilidad

Después de desplegar, abre el juego desde **Ports** y comprueba sin teclado ni ratón:

1. La cruceta navega por inicio, pausa, fin de partida y opciones.
2. A confirma, B vuelve, Select abre opciones y Start pausa/continúa.
3. Start + Select cierra el juego.
4. Puedes iniciar, volar, pausar, reiniciar y volver al menú sin acciones dobles.
5. SFX, música, mute, volumen y vibración funcionan; los volúmenes persisten tras reiniciar.

Si algún botón no responde, inicia temporalmente el port con:

```sh
R36S_INPUT_DEBUG=1 R36S_FULLSCREEN=1 R36S_APP_DIR=/opt/r36s-app /opt/r36s-app/bin/r36s-flappy
```

El detalle de los eventos queda en `/opt/r36s-app/r36s-flappy.log` cuando se usa el lanzador de Ports. Sin `R36S_INPUT_DEBUG=1`, el log solo conserva el resumen de dispositivos detectados.
